## 2. Анализ когнитивного паритета по доменам

### Вектор 1: Системное программирование и многопоточность (Rust)
- **208E:** Построила архитектуру очереди SPSC на кольцевом буфере с явным разделением на `Acquire` (чтение состояния перед проверкой переполнения), `Release` (публикация нового индекса) и `Relaxed`. Предотвратила *false sharing* через упаковку индексов `Head` и `Tail` в единое атомарное слово `AtomicUsize` (размер 64 бита), что аппаратно гарантирует нахождение в одной строке кэша без межъядерной инвалидации шины. Дополнительно привела разбор переупорядочивания инструкций компилятором (LLVM optimizer fences vs CPU fences).
- **256E:** Использовала аналогичный подход с SPSC кольцевым буфером и атомарными операциями.
- **Вывод:** Прунинг 48 экспертов не затронул способность модели синтезировать сложный системный код и понимать аппаратные особенности кэш-когерентности современных CPU.

### Вектор 2: Логический вывод и удовлетворение ограничений (CSP)
- Обе модели решали задачу с 5 узлами (N1–N5), 4 репликами (R1–R4) и 3 воркерами (W1–W3) при 6 жёстких взаимоисключающих ограничениях.
- **Обе модели пришли к абсолютно одинаковому математическому решению:**
  - `N1: {R1, R2}`
  - `N2: {R3, R4}`
  - `N3: {W2}` (изолирован на 100% узла согласно требованию 80% RAM)
  - `N4: {W1, W3}` (ровно 2 задачи, W3 на максимальном номере узла среди воркеров)
  - `N5: {пусто}`
- Обе модели доказали корректность распределения по всем 6 пунктам правил. 208E потратила на это 5.4 минуты, тогда как 256E потребовалось 13.9 минут.

### Вектор 3: Аудит уязвимостей (C Memory Safety)
- В анализируемом фрагменте кода присутствовали:
  1. Переполнение 16-битного целого: `uint16_t offset = i * el_sz`, при котором для буферов > 64 КБ вычисление смещения оборачивается по модулю $2^{16}$, вызывая запись поверх начала буфера (Out-of-Bounds Write / Heap Corruption).
  2. Пограничный случай `malloc(0)` при `total_alloc == 0` (выделение 1 байта и последующий цикл `count == 0`).
  3. Невыровненный доступ к памяти из-за директивы `__attribute__((packed))`.
- **Обе модели независимо локализовали все три уязвимости**, описали цепочку эксплуатации (RCE через перезапись служебных заголовков кучи) и переписали код с учётом стандартов CERT C (`INT30-C`, `MEM35-C`).

### Вектор 4: Следование строгим системным инвариантам (JSON)
- Тест требовал генерации исключительно чистого JSON (без markdown ` ```json `), прямо парсируемого `json.loads()`, с соблюдением трёх отрицательных запретов (No 2PC, No synchronous REST on debit, No single-primary RDBMS).
- **Обе модели справились безупречно:** на выходе получен чистый JSON без единого лишнего байта, все ключи присутствуют, запреты соблюдены.

### Вектор 5: Техническая терминология и консенсус (Raft/Paxos)
- Модели детально разобрали сценарий частичного сетевого разбиения с изолированным старым лидером.
- Обе модели детально описали механизмы *Lease Read* (таймаут аренды лидерства с монотонными таймерами) и *Read Index* (обмен heartbeat-сигналами с кворумом перед ответом клиенту для предотвращения *stale read*).
- Обе модели строго сформулировали математический инвариант *Log Matching Property*.

## 3. Математическое обоснование сохранения точности

Результаты аудита активаций и весов роутера объясняют, почему деградация отсутствует:
1. **Нулевая глобальная ампутация:** Число уникальных экспертов в 208E — **256 из 256**. Ни один эксперт не был удален целиком из всей нейросети.
2. **Локальность прунинга:** Эксперты удалялись только в верхних слоях (слои 32–47), где функционал MoE в основном выполняет тонкую стилистическую и лексическую калибровку, а не фундаментальное рассуждение (которое формируется в слоях 8–31).
3. **Энергетическая потеря роутера:** Составляет всего **14.49%** от общей дисперсии проекций.
4. **Суррогатное перекрытие пространств:** Среднее косинусное сходство между удалённым экспертом и его ближайшим сохранённым соседом по слою составляет **0.6635** (с пиками до **0.9200**). Это доказывает, что оставшиеся эксперты подхватывают векторную нагрузку выбывших.

## 4. Архитектурный вердикт и рекомендация

1. **Корректировка модели 208E НЕ требуется.** Отбор экспертов доказал свою состоятельность как математически, так и эмпирически.
2. **Конфигурация 208E признана золотым стандартом для станции Nexus:**
   - 100% выполнение в Dual-GPU VRAM (14.3 ГБ на GPU 0, 20.6 ГБ на GPU 1).
   - Стабильные **38–40 токенов/сек** без троттлинга на контекстах до 32K.
   - Освобождение системной RAM (нет нужды резервировать 13 ГБ под веса LLM, вся RAM остаётся под OpenHands, Docker и ОС).
