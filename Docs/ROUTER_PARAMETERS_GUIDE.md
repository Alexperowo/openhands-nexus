# Справочник параметров роутера (llama-swap) и движка инференса (llama-server)

Данный документ представляет собой полное руководство по параметрам конфигурации локального роутера **llama-swap** и управляемого им движка **ik_llama (llama-server)** рабочей станции OpenHands Nexus.

Параметры разделены на две фундаментальные категории:
1. **Часто используемые экспертом** — ключевые рычаги производительности, распределения VRAM/GPU, контекста, MTP-ускорения и бюджетирования рассуждений.
2. **Редко используемые (Advanced / Edge Cases)** — тонкий тюнинг системной памяти, специфические сэмплеры, аппаратные хаки и специализированные сценарии.

---

## 1. Параметры верхнего уровня: llama-swap

Файл конфигурации: [`llama-swap/config.yaml`](file:///k:/Project/llama-swap/config.yaml)  
CLI запуск: `llama-swap.exe -config config.yaml -listen 127.0.0.1:8080 -watch-config`

### 1.1 Часто используемые параметры llama-swap

| Параметр | Уровень | Описание и экспертное применение |
| :--- | :--- | :--- |
| `models.<id>.cmd` | Модель | **Команда запуска процесса бэкенда**. Содержит полный путь к `llama-server.exe` и все флаги инициализации модели. Обязательно включает маркер `${PORT}`, который роутер динамически заменяет на свободный порт (5801, 5802 и т.д.). |
| `models.<id>.proxy` | Модель | **Адрес внутреннего проксирования** (`http://127.0.0.1:${PORT}`). Указывает роутеру, куда перенаправлять HTTP/WebSocket запросы OpenAI API после успешного старта инстанса. |
| `models.<id>.aliases` | Модель | **Таблица псевдонимов модели**. Позволяет клиентам (OpenHands, LiteLLM, curl) обращаться к модели под разными именами (например, `openai/qwen`, `qwen`, полный путь к файлу `.gguf`). |
| `models.<id>.unloadTimeout` | Модель | **Таймаут выгрузки из VRAM (в секундах)** при отсутствии запросов. Экспертное значение: `15` секунд для быстрой динамической ротации в рамках VRAM-бюджета (37.9 GB), либо `3600`, если модель должна быть постоянно прогрета. |
| `models.<id>.cmdStop` | Модель | **Команда гарантированной остановки процесса**. На Windows: `powershell -NoProfile -Command "Stop-Process -Id ${PID} -Force; Start-Sleep -Seconds 3"`. Предотвращает появление процессов-сирот и утечки дескрипторов портов. |
| `models.<id>.env` | Модель | **Переменные окружения дочернего процесса**. Например, `GGML_CUDA_NO_PINNED=0` (управление пиннингом хостовой памяти CUDA). |
| `-watch-config` | CLI флаг | **Горячая перезагрузка конфигурации**. Заставляет `llama-swap` отслеживать изменения `config.yaml` на диске и применять новые параметры при следующем вызове модели без перезапуска самого роутера. |
| `-listen` | CLI флаг | **Сетевой сокет прослушивания** (по умолчанию `127.0.0.1:8080`). Маршрутизирует все внешние входящие запросы. |
| `logLevel` | Глобальный | Уровень детализации логов: `debug`, `info`, `warn`, `error`. Для отладки ротации и переключения слотов используется `debug`. |
| `logToStdout` | Глобальный | Направление вывода логов: `both`, `stdout`, `stderr`, `none`. `both` обеспечивает захват как в терминал, так и в пайпы фоновых служб. |

### 1.2 Редко используемые параметры llama-swap

| Параметр | Уровень | Описание и сценарии применения |
| :--- | :--- | :--- |
| `healthCheckTimeout` | Глобальный | **Таймаут проверки готовности сервера (сек)**. По умолчанию `1200`. Критичен при первой загрузке сверхтяжёлых моделей (Qwen 122B на RAM offload), когда прогрев модели и инициализация весов занимает 40–90 секунд. |
| `healthCheckPath` | Модель | Кастомный путь проверки жизнеспособности (по умолчанию опрашивается эндпоинт `/health` или `/v1/models`). Редко требуется переопределять. |
| `peers` | Глобальный | **Таблица пиринга роутеров**. Позволяет объединять несколько физических серверов с `llama-swap` в распределённый кластер для перенаправления запросов между разными машинами. |
| `-tls-cert-file` / `-tls-key-file` | CLI флаг | Встроенная TLS-терминация на уровне `llama-swap`. В архитектуре Nexus редко используется напрямую, так как HTTPS/WSS терминация возложена на защищённый внешний шлюз `openhands-pwa/lan-gateway.mjs` (порт 8443). |
| `-config-dir` | CLI флаг | Директория с раздельными YAML-файлами конфигураций моделей (аддитивна к `-config`). Используется в гигантских инфраструктурах с десятками моделей. |
| `-listen-tailcat` | CLI флаг | Путь к приватному ключу Tailscale/Tailcat для прямой интеграции роутера в mesh-сеть без внешнего VPN-клиента. |

## 2. Параметры движка инференса: llama-server (ik_llama)

Управляются строкой `cmd: >-` в конфигурации `llama-swap`.

---

### 2.1 Часто используемые экспертом параметры

#### А. Модель, память и видеокарты
1. **`-m <path>` (`--model`)**  
   Абсолютный путь к целевому файлу квантованной модели в формате GGUF.
2. **`-c <N>` (`--ctx-size`)**  
   Размер контекстного окна в токенах.
   - *В Nexus:* `131072` (128K) для полной кодовой аналитики.
3. **`-ngl <N>` (`--n-gpu-layers`)**  
   Количество слоёв нейросети, выгружаемых в VRAM.
   - `999` — все слои загружаются в GPU (Qwen 3.8, Ornith 1.5, Next 80B).
   - `37` — гибридный оффлоад для Qwen 122B (37 слоёв в 38 GB VRAM, остальные в 48 GB RAM).
4. **`-dev <CUDA0,CUDA1,...>`**  
   Явное назначение физических видеокарт для процесса.
   - `-dev CUDA1` — изоляция модели на RTX 2080 Ti 22 GB, освобождая RTX 5060 Ti под UI, десктоп и голос.
   - `-dev CUDA0,CUDA1` — объединение двух GPU в единый пул памяти.
5. **`-ts <split>` (`--tensor-split`)**  
   Пропорция распределения слоёв между GPU.
   - Для пула 16GB + 22GB: `-ts 14,22` (для Next 80B) или `-ts 13.5,22.5` (для Qwen 122B).
6. **`-fa on` (`--flash-attn`)**  
   Активация Flash Attention. Снижает квадратичную сложность внимания, экономит до 50% VRAM при длинных контекстах (от 16K до 128K) и ускоряет инференс.

#### Б. Квантование KV-кэша
7. **`-ctk <type>` (`--cache-type-k`)** и **`-ctv <type>` (`--cache-type-v`)**  
   Тип квантования контекстного кэша ключей и значений:
   - `-ctk q8_0 -ctv q5_0` — эталонный баланс для Ornith 1.5 (максимальная точность при низком расходе памяти).
   - `-ctk q6_0 -ctv q4_0` — высокоэффективное квантование для длинного контекста 128K в Next 80B и Qwen 122B.

#### В. Рассуждение (Reasoning / Thinking)
8. **`--reasoning-budget <N>`**  
   Максимальный бюджет токенов, разрешённый модели на пребывание внутри блока `<think>`.
   - `3072` — для Ornith 1.5 и Qwen 122B (предотвращает исчерпание контекста).
   - `4096` — для Qwen 3.8 Opus и Qwen 3 Next.
   - `-1` — без ограничений. `0` — принудительное отключение размышлений.
9. **`--reasoning-format <format>`**  
   Формат обработки мыслей. Режим `deepseek` автоматически отделяет внутренний монолог модели и помещает его в поле `message.reasoning_content` API-ответа, очищая основной `content` для OpenHands.
10. **`--reasoning-budget-message "<text>"`**  
    Инъекция системного триггера перед закрывающим тегом `</think>` при исчерпании лимита (например, `"Conclude reasoning immediately and output the final answer now."`). Заставляет модель мгновенно перейти к синтезу ответа.
11. **`--jinja`**  
    Использование оригинального Jinja-шаблона токенизатора модели. Критично для поддержки флагов `chat_template_kwargs` (`enable_thinking`, `reasoning_effort`).

#### Г. Спекулятивное ускорение (MTP)
12. **`--spec-type <spec>`**  
    Активация Multi-Token Prediction или спекулятивного драфта:
    - `--spec-type mtp:n_max=3,p_min=0.05` — чемпионская конфигурация для Qwen 3.8 Opus (+49% ускорения генерации).
    - `--spec-type mtp:n_max=1,p_min=0.50` — оптимальный режим для Ornith 1.5 (+8% ускорения, стабильные 68–78 т/с).

#### Д. Сэмплирование и параллелизм
13. **`-np 1` (`--parallel`)**  
    Количество параллельных слотов выполнения. Для рабочей станции с выделенным агентом фиксируется в `1`, гарантируя 100% выделение VRAM и кэша под один активный диалог.
14. **`-t 6` (`--threads`)**  
    Количество потоков CPU для вычислений вне GPU.
15. **`--temp`, `--top-p`, `--min-p`, `--top-k`**  
    Базовые гиперпараметры сэмплирования модели на уровне сервера.
16. **`--mmproj <path>`**  
    Путь к мультимодальному проектору для моделей со зрением (Vision).

#### Е. Аппаратное ускорение MoE (Hot-Expert Cache & Tensor Override)
17. **`--moe-expert-cache <N>`**  
    Количество слотов горячего кэша экспертов на GPU для каждого MoE-слоя (Upstream PR #27861). Удерживает самые востребованные матрицы экспертов прямо в видеопамяти по алгоритму LRU, снижая PCIe/RAM задержки до нуля.
    - `64` — штатный режим Qwen 122B (полный контекст 128K, ~26.5 tok/s).
    - `80` — экстремальный режим кодинга (контекст 96K, пиковая скорость **33.01 tok/s**).
18. **`--moe-expert-cache-inserts <N>`**  
    Максимальное количество вставок новых экспертов в кэш за один шаг генерации (по умолчанию `2`). Предотвращает трэшинг кэша при резкой смене тематики.
19. **`-ot <pattern>=<backend>` (`--override-tensor`)**  
    Точечное переопределение целевого бэкенда для конкретных тензоров по регулярному выражению.
    - В связке Qwen 122B: `-ot "blk\.(3[3-9]|4[0-7])\.ffn_(up|gate|down)_exps=CPU"` выгружает в RAM исключительно тяжелые экспертные матрицы верхних 15 слоев, оставляя роутеры (`ffn_gate_inp`) и механизмы внимания на GPU.

### 2.2 Редко используемые параметры llama-server (Advanced / Edge Cases)

| Параметр | Назначение и экспертная оценка |
| :--- | :--- |
| **`-sm <mode>` (`--split-mode`)** | Режим разбиения слоев между GPU: `none`, `layer`, `row`. По умолчанию `layer`. Режим `none` отключает параллелизм, фиксируя инференс на одной карте. Режим `row` дробит матричные умножения построчно (требует NVLink / высокую пропускную способность PCIe). |
| **`-b <N>` / `-ub <N>`** | **`--batch-size` и `--ubatch-size`**. Логический размер батча (по умолчанию 2048) и физический микробатч (512). Тюнинг полезен при нехватке VRAM во время prefill-фазы длинных промптов (уменьшение `-ub 256` спасает от OOM при 64K+ промптах). |
| **`--no-mmap`** | **Запрет отображения файла весов в виртуальную память**. Заставляет сервер целиком загружать GGUF в физическую RAM через `read()`. Редко используется, так как увеличивает время старта, но полезно при работе с медленными сетевыми дисками. |
| **`--mlock`** | **Блокировка страниц памяти в RAM**. Предотвращает сброс весов модели в Windows Pagefile (своп). Полезно для исключения внезапных лагов, если в системе мало свободной оперативной памяти. |
| **`--numa <mode>`** | **NUMA-оптимизация** (`distribute`, `isolate`, `numactl`). Критична для многосокетных серверов (2x AMD EPYC / Dual Xeon) для устранения межсокетных задержек шины Infinity Fabric. На односокетных ПК влияния не оказывает. |
| **`--defrag-thold <N>`** | Порог фрагментации KV-кэша (по умолчанию `-1.0`). Принудительно запускает компактизацию памяти контекста при сильной фрагментации сессий. |
| **`--context-shift`** | **Циклический сдвиг контекста**. Позволяет серверу автоматически выбрасывать старые токены из начала кэша при переполнении контекстного окна вместо возврата ошибки `context limit exceeded`. В OpenHands не рекомендуется, так как ломает агентский контроль истории. |
| **`--prompt-cache <file>`** | Сохранение состояния KV-кэша системного промпта на диск. Позволяет мгновенно стартовать инференс без повторного вычисления базового промпта OpenHands. |
| **`--prompt-cache-all`** | Сохранение кэша всех пользовательских сессий на диск. Редко используется из-за гигантского расхода дискового пространства SSD (десятки гигабайт на сессию). |
| **`--dry-multiplier` / `--dry-base`** | **DRY (Don't Repeat Yourself) сэмплер**. Динамически штрафует повторяющиеся n-граммы и циклы в коде. Эффективно подавляет зацикливание при кодогенерации, если стандартный `repeat-penalty` не справляется. |
| **`--xtc-probability` / `--xtc-threshold`** | **XTC (Exclude Top Choices)**. Сэмплер, отсекающий очевидный токен номер один, заставляя модель писать менее шаблонный и более творческий код/текст. |
| **`--mirostat` / `--mirostat-tau`** | Алгоритм адаптивного сэмплирования Mirostat 2.0. Автоматически удерживает сложность (перплексию) текста около целевого значения `tau`. |
| **`--rope-scaling <type>`** | Масштабирование позиционных эмбеддингов RoPE (линейное, `yarn`). Позволяет искусственно расширять контекст модели (например, с 32K до 128K), если модель исходно не была обучена на длинный контекст. |
| **`--rope-freq-base` / `--rope-freq-scale`** | Базовая частота и масштаб частот RoPE для тонкой настройки контекстной геометрии внимания. |
| **`--lora <file>` / `--lora-scaled`** | Наложение LoRA-адаптеров поверх базовой GGUF модели «на лету» без необходимости полного слияния (merge) весов. |
| **`--grp-attn-n` / `--grp-attn-w`** | Параметры Group Attention для вычислений по алгоритму YaRN на сверхдлинных контекстах. |
| **`--slots-endpoint-disable`** | Отключение эндпоинта `/slots` для закрытия телеметрии слотов от внешних клиентов локальной сети. |
| **`--api-key <secret>`** | Авторизация на уровне движка инференса. В Nexus не требуется, так как аутентификация и защита LAN возложена на шлюз `lan-gateway.mjs`. |
| **`--skip-chat-parsing`** | Принудительное отключение парсинга чат-шаблона. Модель выдаёт весь сырой текст, включая служебные токены размышления и tool-calling, в секцию `content`. Полезно исключительно для низкоуровневой отладки. |
| **`GGML_CUDA_NO_PINNED=1`** | Запрет пиннинга памяти хоста CUDA. Предотвращает зависания при дефиците свободной физической RAM на стороне драйвера NVIDIA. |
