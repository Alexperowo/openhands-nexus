# Первый запуск

Как поставить Nexus на только что установленную Ubuntu Cinnamon.
Всё делается в терминале; на вопросы установщика отвечать «д» (да) или «н» (нет).
Просто Enter — ответ по умолчанию, он показан большой буквой: `[Д/н]` — да, `[д/Н]` — нет.

## 1. Что нужно

- Ubuntu 26.04 Cinnamon, подключённая к интернету.
- Видеокарты NVIDIA: RTX 5060 Ti и RTX 2080 Ti (работает и с одной из них).
- Свободное место: около 15 ГБ под программы и до 80 ГБ под модели.
- Архив движка `ik_llama-….bundle` и файл `ik_llama-….bundle.sha256` — они лежат рядом с архивом проекта.
  Положить оба в папку `~/Nexus-архивы/`: тогда движок собирается без GitHub.
  Без них установщик скачает исходники движка сам.
- Если есть — личная копия `nexus-personal-….tar.gz` (ключи, сертификат планшета, беседы).
  Её положить в папку `~/Nexus-архивы/личное/`, установщик найдёт её сам.

## 2. Распаковать архив

```bash
mkdir -p ~/Agents
tar xf OpenHands-Nexus-linux-*.tar.gz -C ~/Agents
cd ~/Agents/OpenHands-Nexus
```

Переустановка системы на этом же ПК и есть архив этого ПК `nexus-own-….tar.zst` (`./pack own`) —
распаковать вместо архива проекта его: собирать движок не придётся.

```bash
tar xf nexus-own-*.tar.zst -C ~
cd ~/Agents/OpenHands-Nexus
```

## 3. Установить

```bash
./install
```

Установщик идёт по шагам и про каждый пишет, что делает. Уже сделанное пропускает,
поэтому после перерыва или ошибки достаточно снова запустить `./install`.
Пароль спрашивает только системная команда `sudo`, если он нужен.

Шаги по порядку:

1. **Системные программы** — git, сборщики, звук, KDE Connect.
2. **Драйвер видеокарты.** После него установщик попросит перезагрузить компьютер.
   После перезагрузки снова `cd ~/Agents/OpenHands-Nexus` и `./install`.
3. **CUDA** — набор для вычислений на видеокарте.
4. **Node и uv** — среды для интерфейса и голоса.
5. **Движок моделей** (ik_llama) — собирается из исходников, это 30–60 минут.
   Готовый движок с другого компьютера не переносится: он собирается под процессор и видеокарты.
6. **llama-swap и Caddy** — переключатель моделей и шлюз для планшета.
7. **Интерфейс, голос, управление экраном** — скачиваются и собираются.
8. **Ключи и сертификат.** Есть личная копия — восстанавливается из неё
   (ничего существующего не перезаписывается). Нет — создаются новые.
9. **Модели.** Установщик спросит папку для моделей и по каждой модели — скачивать ли.
   Скачивание долгое; прервалось — повторный `./install` продолжит с того же места.
   Каждый файл проверяется по контрольной сумме.
10. **Видеокарты** — привязка запасных моделей к картам этого компьютера.
11. **Wi-Fi.** Если Wi-Fi-карта MediaTek, установщик предложит отключить функцию TDLS:
    с ней планшет теряет связь с ПК на 15 секунд. Ответить «д».
12. **Службы и ярлыки** на рабочем столе. Автозапуска нет: Nexus запускается только ярлыком.
13. **Настройка агента** — профили моделей и подсказка агента из проекта.

В конце установщик пишет, всё ли готово, или чего не хватает.

## 4. Первый запуск

1. Ярлык **«Запустить Nexus»** на рабочем столе.
2. Подождать: модель загружается 1–2 минуты. Когда всё готово, Nexus скажет об этом голосом
   и покажет уведомление с адресом для планшета.
3. На ПК открыть в браузере `https://localhost:8443/`.

Важно: адрес **8443** — это Nexus. Адрес 8010 — голый OpenHands без доработок, им не пользоваться.

## 5. Планшет

Один раз, при первой установке или если сертификат создан заново:

1. Узнать адрес ПК: в терминале `hostname -I`, первое число вида `192.168.0.…`.
2. На планшете, пока Nexus запущен, открыть в Chrome `http://<адрес ПК>:8081/ca.crt`.
3. Установить скачанный файл: Настройки → Безопасность → Другие параметры безопасности →
   Установить с устройства → Сертификат ЦС.
4. Открыть `https://<адрес ПК>:8443/`, в меню Chrome — «Добавить на главный экран» → «Установить».

Если сертификат восстановлен из личной копии, планшет уже ему доверяет, шаги 2–3 не нужны.

## 6. Уведомления на планшет (KDE Connect)

1. На планшете поставить приложение KDE Connect, ПК и планшет — в одной Wi-Fi-сети.
2. В приложении выбрать этот ПК и нажать «Запросить сопряжение», на ПК — принять.

Через KDE Connect приходят сообщения о готовности и о сбоях.

## 7. Проверка

```bash
./check
```

Проверяет все части по очереди и пишет итог по каждой. Код 1 — что-то не прошло, причина в выводе.
