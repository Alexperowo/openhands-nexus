# Тестирование Vision в системной RAM (--no-mmproj-offload)

## 1. Цель испытания
Проверить стабильность, скорость и потребление памяти универсального запуска Ornith-1.5-35B с мультимодальным проектором `mmproj-Ornith-1.5-35B-BF16.gguf`, удерживаемым в системной оперативной памяти (CPU RAM) через флаг `--no-mmproj-offload` с многопоточной обработкой `-tm 8` на контексте 96K (98304 токена) и MTP.

## 2. Конфигурация запуска
- **Бэкенд**: `K:\Project\ik_llama\bin\llama-server.exe` (commit `3c58ae3`)
- **Модель**: `K:\Project\Models\Ornith-1.5-35B-MTP-19G-ICE.gguf`
- **Проектор**: `K:\Project\Models\mmproj-Ornith-1.5-35B-BF16.gguf`
- **Флаги**: `-c 98304 -ctk q8_0 -ctv q5_0 -fa on -ngl 999 -np 1 -dev CUDA0 --spec-type mtp:n_max=1,p_min=0.75 --jinja --no-mmproj-offload -tm 8`
- **Тестовое изображение**: `K:\Project\OpenHands-Tests\Android-Smoke-01\initial-screen.png` (скриншот экрана планшета 1080x2400)

---

## 3. Фактические результаты измерений

| Метрика | Значение в тесте | Примечание |
|---|---|---|
| **Начальная VRAM** | 491 MiB | Чистая система перед запуском |
| **VRAM после загрузки 96K+MTP+mmproj(RAM)** | **20 226 MiB** | Свободно **2 005 MiB** (запас >2 GB!) |
| **Системная RAM** | 27.85 GB / 47.92 GB (58%) | Включает модель проектора и буферы |
| **Время генерации текста (100 tok)** | **2.28 с** | Генерация **74.6 tok/s**, драфт 42/57 |
| **Пиковая VRAM при генерации текста** | **20 356 MiB** | Стабильно, запас 1.9 GB |
| **Время кодирования изображения на CPU (`-tm 8`)** | **339 688 мс (5.66 мин)** | 1 слайс обрабатывался 5.6 минут! |
| **Результат декодирования изображения** | **FAIL (`ret = -3`)** | `mtmd_helper_eval failed with status -3` |
| **Причина ошибки декодирования** | Ошибка перекрёстного переноса тензоров между CPU mmproj и GPU-контекстом на границе батча 2048 |

---

## 4. Анализ и технические выводы

1. **Экономия VRAM подтверждена**:
   - Удержание mmproj в RAM действительно снижает расход видеопамяти с 22 034 MiB до **20 226 MiB** (освобождая ~1.8 GB VRAM).
2. **Катастрофическая задержка на CPU**:
   - Без тензорных ядер GPU обработка высокого разрешения (1080x2400) занимает **почти 6 минут** на один кадр.
   - Для интерактивного агента и UI-автоматизации (Android MCP / Web) задержка 6 минут на скриншот является критически неприемлемой (OpenHands и сетевые клиенты завершают запрос по таймауту 120-300 с).
3. **Сбой декодирования**:
   - `llama-server` завершает шаг с ошибкой `llama_decode: failed to decode, ret = -3`, что делает режим технически нестабильным в текущей версии бэкенда.

## 5. Итоговое решение
- **НЕ добавлять** `--no-mmproj-offload` в производственный скрипт [`BEST-ORNITH15-96K.cmd`](file:///K:/Project/LLM-tests/BEST-ORNITH15-96K.cmd).
- Оставить `BEST-ORNITH15-96K.cmd` оптимизированным под чистый текст, кодинг и инструменты (74.6 tok/s, 96K, MTP).
- При необходимости работы с Vision запускать проектор на GPU с меньшим контекстом (как проверено в тестах на 16K, где распознавание занимает считанные секунды).
