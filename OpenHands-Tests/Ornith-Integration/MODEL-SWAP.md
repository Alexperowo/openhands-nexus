# Архитектура и управление сменой моделей (llama-swap)

## 1. Назначение и принцип работы
Поскольку модели Qwen3.8-27B (~20.8 GB VRAM) и Ornith-1.5-35B (~20.4 GB VRAM) не могут одновременно находиться в физической памяти карты RTX 2080 Ti (22.5 GB), используется маршрутизирующий прокси **`mostlygeek/llama-swap`**.

- **Прокси-сервер**: слушает локальный порт `http://127.0.0.1:8080` (входная точка для OpenHands).
- **Динамический запуск**: при поступлении запроса с `model: "qwen"` или `model: "ornith"` прокси автоматически:
  1. Проверяет, запущен ли требуемый бэкенд.
  2. Если запущен другой бэкенд — посылает сигнал корректного завершения старому процессу.
  3. Дожидается подтверждения завершения процесса и полного освобождения VRAM.
  4. Запускает требуемый бэкенд на внутреннем динамическом порту `${PORT}`.
  5. Дожидается прохождения health-check (`/health` -> 200 OK).
  6. Проксирует исходный запрос и возвращает ответ клиенту.

## 2. Контроль владения процессами (Ownership) и выживаемость чужих процессов

В соответствии со строгим инвариантом OpenHands Local, запрещены любые операции `kill-by-name` (`Get-Process llama-swap | Stop-Process -Force` или `taskkill /IM llama-server.exe /F`).

Реализована схема строгого владения:
1. **START** (`K:\Project\llama-swap\start-swap.ps1`):
   - Проверяет доступность порта 8080 (`/health`).
   - Если прокси уже запущен сторонним процессом / сессией: фиксирует `session.json` с `owned = false, pid = null`. Чужой процесс используется повторно, но лаунчер им не владеет.
   - Если порт свободен: запускает `llama-swap.exe`, фиксирует точный `PID` и выставляет `owned = true`.
2. **STOP** (`K:\Project\llama-swap\stop-swap.ps1`):
   - Считывает `session.json`.
   - Если `owned == true`: сначала вызывает `POST http://127.0.0.1:8080/api/models/unload` для выгрузки моделей и освобождения VRAM, затем завершает **только** зафиксированный `PID` и его прямых потомков.
   - Если `owned == false`: выводит `[SKIP]` и **не завершает** чужой процесс.

### Детерминированный тест выживаемости (Foreign-Process Survival Test)
- **Тестовый скрипт**: `K:\Project\OpenHands-Tests\Ornith-Integration\test_foreign_survival.py`
- **Ход теста**:
  1. Запущен сторонний процесс `llama-swap.exe` на тестовом порту 18095 (PID 12056).
  2. Выполнен запуск `start-swap.ps1 18095` -> успешно распознан pre-existing инстанс, в `session.json` записано `owned: false`.
  3. Выполнен запуск `stop-swap.ps1` -> скрипт зарегистрировал `owned == false`, пропустил завершение (`[SKIP]`).
  4. Проверка: PID 12056 **остался жив и полностью отзывчив** (`/health` -> 200 OK).
- **Результат**: **PASS**.

## 3. Интеграция в штатный цикл OpenHands Local (`start.ps1` / `stop.ps1`)

Устранён исторический конфликт, при котором `start.ps1` напрямую занимал порт 8080 процессом `llama-server.exe`:

- **Итоговая архитектура**:
  ```
  START-OPENHANDS-LOCAL (start.ps1)
  ├── 1. owned llama-swap (порт 8080, динамическая загрузка Qwen / Ornith)
  ├── 2. Local Voice Bridge (порт 18002)
  └── 3. OpenHands Agent Canvas / Server (порты 8000, 18000, 18001)
  ```
- **Правила владения**:
  - `start.ps1` проверяет порт 8080. Если `llama-swap` уже работает, ставит `swap_owned = false`. Если нет — запускает `llama-swap.exe` в скрытом режиме WMI и сохраняет `swap_pid` в `K:\Project\.openhands-local\session.json`.
  - `stop.ps1` вызывает `/api/models/unload`, затем завершает только собственный `swap_pid`. Если `swap_owned == false`, оставляет `llama-swap` работать.
  - Проверено аппаратным тестом: после остановки платформы видеопамять возвращается к исходным **418 MiB**, порты освобождаются.
