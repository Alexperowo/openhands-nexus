## 1. Архитектура интеграции

```
┌────────────────────────────────────────────────────────────┐
│         OpenHands Agent Canvas (http://localhost:8000)     │
│  [🎙 Mic]  [Auto Send: OFF]  [🔊 TTS: ON]  [■ Stop Speech] │
└─────────────────────────────┬──────────────────────────────┘
                              │ HTTP (Audio / Text / Stop)
                              ▼
┌────────────────────────────────────────────────────────────┐
│      Local Voice Bridge Service (http://127.0.0.1:18002)   │
│  ┌────────────────────────────┐┌─────────────────────────┐ │
│  │   Persistent STT Engine    ││   Persistent TTS Engine │ │
│  │  FUTO GigaAM v3 e2e-RNN-T  ││   Supertonic 3 Russian  │ │
│  │   (transcribe.cpp / GGML)  ││       (Supertone ONNX)  │ │
│  └────────────────────────────┘└─────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- **Принцип работы:** Единый постоянный фоновый HTTP-сервер на `127.0.0.1:18002`. Обе нейросетевые модели (STT и TTS) загружаются в оперативную память один раз при старте сервиса и переиспользуются для всех последующих реплик без перезапуска процессов и без повторного чтения с диска.
- **Полная автономность:** 100% локальное исполнение, нулевые облачные зависимости, нулевой сетевой трафик наружу.
- **Ресурсы GPU:** STT и TTS выполняются на CPU (AVX2), потребляя **0 МБ VRAM** видеокарты и сохраняя все 22 ГБ памяти RTX 2080 Ti для локальной модели Qwen3.8-27B.

## 2. STT (Распознавание речи) — FUTO GigaAM v3

- **Наработка пользователя:** Репозиторий `D:\Project\futo-keyboard-gigaam`.
- **Модель:** `D:\Project\futo-keyboard-gigaam\voiceinput-shared\models\cache\assets\voice-models\gigaam-v3-e2e-rnnt-Q8_0.gguf` (261 МБ) — официальный релиз Conformer-RNN-T от ai-sage/SberDevices с пунктуацией и капитализацией русского текста.
- **Движок:** `transcribe.cpp` (на базе `ggml`). Скомпилирован под Windows x64 через MSVC 2022 (`transcribe.dll` и `transcribe-cli.exe`).

## 5. Интеграция в интерфейс OpenHands Agent Canvas

### Анализ официального механизма расширений
Исследование установленного пакета `@openhands/agent-canvas 1.16.0` показало:
- Официальный `CanvasExtensionHost` поддерживает регистрацию только отдельных страниц в боковом меню через метод `registerPage(contributionId, mount)`.
- Официальных слотов расширения, хуков или декораторов для центрального поля ввода сообщений чата (`ChatInput` / `ConversationPanel`) в архитектуре Agent Canvas **не предусмотрено**.

### Реализованный минимально инвазивный метод
1. Клиентский модуль: `K:\Project\local-voice\voice-bridge.js` и стили `voice-bridge.css`.
2. Раздача ассетов: локальный Voice Bridge на `127.0.0.1:18002` напрямую отдаёт JS и CSS через HTTP, исключая зависимость от кеширования и бандлинга Agent Canvas.
3. Инъекция: скрипт `K:\Project\local-voice\patch-agent-canvas-voice.ps1` однократно добавляет теги перед `</body>` в `build/index.html`.
4. Бэкап: исходный файл зафиксирован в `build/index.html.original`.
5. **Авто-восстановление при обновлениях:** Скрипт `start.ps1` перед каждым запуском платформы автоматически проверяет наличие инъекции и восстанавливает её при необходимости. Обновление Agent Canvas через npm переживается бесшовно.

### Элементы управления в UI
- **Кнопка 🎙 (Микрофон):**
  - Серый значок: режим ожидания (Готов).
  - Красная пульсация: запись звука с системного микрофона Windows (Web Audio API 16 кГц).
  - Жёлтый бейдж: быстрое распознавание (Распознавание...).
- **Тумблер Auto Send (по умолчанию OFF):**
  - При OFF: текст вставляется в поле ввода чата, ожидая ручной правки или нажатия Send.
  - При ON: сообщение автоматически отправляется в чат через 200 мс после завершения распознавания.
- **Тумблер 🔊 TTS (по умолчанию ON):** Включение/выключение озвучивания ответов агента.
- **Кнопка ■ Stop Speech (Прерывание):** Мгновенная остановка синтеза и воспроизведения.
- **Фильтрация вывода:** Синтезируется только чистый текст финального ответа ассистента. Блоки `<think>`, reasoning-content, вызовы MCP tools, логи терминала и системные подсказки автоматически отсекаются.
- **Сохранение настроек:** Положения тумблеров сохраняются в `localStorage` браузера.

## 6. Механизм прерывания (Barge-In / Stop Speech)

В соответствии с требованием пользователя реализована двусторонняя мгновенная отмена:
1. **При нажатии кнопки Stop:**
   - В браузере: вызов `Audio.pause()`, сброс `currentTime = 0`, очистка `src`, вызов `AbortController.abort()` для отмены входящего HTTP-запроса синтеза.
   - На сервере: отправка `POST /stop`, выставляющая `cancel_event` и прерывающая генерацию ONNX в генераторе речи.
   - **Задержка отмены:** **1.7 мс** (сервер возвращает HTTP 204 No Content).
2. **При нажатии Микрофона во время речи (Barge-in):**
   - Воспроизведение речи останавливается **мгновенно**, не дожидаясь окончания аудиофайла.
   - Микрофон сразу переходит в режим `LISTENING` и начинает захват новой фразы пользователя.

## 7. Управление через START и STOP launchers

- **Файл сессии:** `K:\Project\.openhands-local\session.json` расширен параметрами:
  - `voice_owned: true/false`
  - `voice_pid: <PID>`
- `START-OPENHANDS-LOCAL.cmd`:
  - Проверяет `127.0.0.1:18002/health`.
  - Если Voice Bridge уже работает: переиспользует его (`voice_owned = false`).
  - Если не запущен: запускает фоновый сервис Python, ожидает готовности моделей и сохраняет `voice_owned = true`, `voice_pid`.
- `STOP-OPENHANDS-LOCAL.cmd`:
  - Проверяет флаг `voice_owned`.
  - Если `true`: отправляет штатный `POST /shutdown` и при необходимости завершает только собственный процесс `voice_pid`.
  - Если `false`: оставляет внешний сервис нетронутым.
  - Порты 8000, 8080, 18000, 18001, 18002 корректно освобождаются.
