# OpenHands-Nexus для Linux

Локальный автономный агент на базе [OpenHands Agent Canvas](https://www.npmjs.com/package/@openhands/agent-canvas)
с доступностью для слабовидящего пользователя: крупный русский интерфейс, озвучка ответов,
голосовой ввод, звуковые сигналы и управление с планшета (Chrome PWA по HTTPS в домашней сети).

Ядро OpenHands не меняется: это npm-пакет точной версии. Всё своё — надстройка рядом с ним.
Ветка `master` — прежняя версия для Windows.

## Устройство

| Папка | Что это | Служба, порт |
|---|---|---|
| `agent/` | Agent Canvas как зависимость (agent-server, automation); состояние в `agent/state/`, настройки агента и LLM-профили в `agent/config/` | `ohn-agent`: 8010, 18010, 18011 |
| `ui/` | Надстройка: React-хост компонентов Canvas, русская локаль, озвучка, диктовка, переключатель моделей | статика через шлюз |
| `voice/` | Распознавание GigaAM v3 и синтез Silero v5.6 (CPU), OpenAI-совместимые `/v1/audio/*` | `ohn-voice`: 18020 |
| `models/` | Меню моделей: [llama-swap](https://github.com/mostlygeek/llama-swap) поверх ik_llama `llama-server` | `ohn-models`: 18030, модели 18040+ |
| `gateway/` | Caddy: HTTPS для планшета, сам подставляет ключ сессии в `/api` и `/sockets` | `ohn-gateway`: 8443 |
| `screen/` | Команды экрана для агента: `desk` от H Company ([hai-drivers](https://pypi.org/project/hai-drivers/), MIT; на них обучена Holo4) — снимок, клик, клавиши, текст, окна; координаты 0–1000 | в терминале агента |
| `guard/` | Страж опасных команд агента (PreToolUse-хук в каждой беседе, в том числе в задачах по расписанию): не даёт убить Nexus, сеанс или систему, менять сеть; личные папки целиком — только в корзину | — |
| `launcher/` | `run.sh` для user-юнитов systemd, смотритель служб `watch.py`, ярлыки «Запустить/Остановить Nexus», `install.sh` | `ohn-watch` |
| `update/` | `nexus-update`: проверка и обновление Canvas, ik_llama, llama-swap, Caddy, голосовых пакетов с откатом | — |
| `install`, `pack`, `docs/` | Установщик на чистую систему, архивы проекта и личной копии, инструкции пользователя | — |

Службы работают прямо из этого клона. Ключи — в `~/.config/openhands-nexus/session.env` (0600),
вне репозитория. Автозапуска нет намеренно: видеокарты делятся с другими задачами.

Рабочая папка бесед — `~/Nexus` (создаётся сама; agent-server заводит в ней git для вкладки изменений).

Страницы Canvas для навыков, задач по расписанию и расширений надстройка не показывает:
задачи по расписанию работают (служба automation, порт 18011), но создаются и смотрятся только через API.

## Установка

На чистой Ubuntu 26.04 Cinnamon — из папки проекта (по шагам для пользователя: `docs/first-run.md`,
повседневная работа: `docs/user-guide.md`):

```bash
./install                 # 13 шагов с вопросами; сделанное пропускает, после перерыва — запустить снова
./install --yes           # ответы по умолчанию, модели не скачивает; --skip driver,wifi — без этих шагов
```

Драйвер — `nvidia-driver-615-open` с подписанными модулями ядра (без DKMS и MOK), после него
перезагрузка и повторный `./install`. CUDA 13.1 и NCCL — из репозитория Ubuntu; Node, uv, llama-swap
и Caddy — релизы точных версий со сверкой SHA-256/512; ik_llama собирается из закреплённого коммита
под процессор и архитектуры найденных карт (исходники — из архива движка, без него с GitHub). Ключи, сертификат и беседы — из личной копии (`./pack personal`),
иначе новые. Автозапуск не включается.

Вручную — то же по частям. Нужны: Linux с systemd (user-сеанс), Node 24, [uv](https://docs.astral.sh/uv/), Python 3.12,
системные `ffmpeg` (распознавание, MP3 и скорость речи) и `libflite1` (произношение латиницы), сборка
[ik_llama.cpp](https://github.com/ikawrakow/ik_llama.cpp) с CUDA.

```bash
(cd agent && npm ci)
(cd ui && npm ci && npm run build)
(cd voice && uv sync --frozen && .venv/bin/python download_models.py)
(cd screen && uv sync --frozen)   # нужны системные xdotool, wmctrl, xclip
```

Бинарники не хранятся в git: положить `caddy` в `gateway/`, `llama-swap` в `models/`.
`models/llama-swap.yaml` берёт `llama-server` и веса через две ссылки в `models/` (вне git):
`llama-server` — на сборку ik_llama, `weights` — на папку с весами (`ln -s`; их делает `./install`).
Страж защищает то, куда они ведут. Веса с адресами на Hugging Face (закреплённые ревизии)
и SHA-256 — `models/weights.json`:

```bash
python3 -I models/weights.py status ПАПКА        # что есть (по размеру); код 1, если чего-то нет
python3 -I models/weights.py get ПАПКА nex25 …   # скачать группы: докачка, сверка SHA-256 до имени
```

Шлюзу нужен корневой сертификат `gateway/ca/openhands-ca.{crt,key}`; планшет доверяет ему,
файл для установки отдаётся по `http://<адрес ПК>:8081/ca.crt`.
Файлы сборки интерфейса шлюз отдаёт с вечным кэшем (в имени хеш содержимого), а страницу
браузер проверяет при каждом открытии: новая сборка видна сразу. Из строк Canvas в сборку попадает
только английский — запасной язык (русский — `ui/src/locales/ru.json`).

```bash
launcher/install.sh   # ключи сессии (один раз), юниты ohn-*, ярлыки на рабочем столе
```

В конце установщик перечисляет, чего ещё не хватает для запуска (то же отдельно:
`python3 -I launcher/preflight.py`): программы, сборки, бинарники, сертификат, голосовые модели,
`llama-server` и веса из `models/llama-swap.yaml`. Голосовые модели сверяются по SHA-256
(`voice/download_models.py`): их читает pickle, подменённый файл выполнил бы свой код.

## Запуск

Ярлык «Запустить Nexus» (или `systemctl --user start ohn.target`) поднимает модель, голос, агента
и шлюз и сообщает о готовности голосом и уведомлением. Планшет: `https://<адрес ПК>:8443/`.
«Остановить Nexus» выгружает модель и освобождает видеокарты.

Смотритель `ohn-watch` (`launcher/watch.py`) — отдельная служба вне агента: агент не может
надёжно чинить собственную основу, а systemd перезапускает только упавший процесс, не
зависший. Раз в 15 с он спрашивает голос (`/health`), модели (`/running`) и шлюз (8443). Служба,
которая запущена, но минуту не отвечает, перезапускается один раз; затем уведомление на ПК
и планшет (KDE Connect): «после перезапуска работает» или «перезапуск не помог» с командой
журнала. Падение, после которого systemd сам поднял службу, и отказ systemd после нескольких
попыток тоже сообщаются. У агента своя проверка 18010 в `run.sh`, о нём смотритель только сообщает.
Остановленную службу смотритель не запускает, за долгую работу не перезапускает: проверки
отвечают и пока модель считает (замер: 5-минутная диктовка, ответ `/health` ≤2 мс).

## Модели

Меню llama-swap держит одну модель за раз. В Canvas каждой модели соответствует LLM-профиль
(`openai/<id из llama-swap.yaml>`, адрес `http://127.0.0.1:18030/v1`, свой `max_input_tokens`);
переключатель под строкой ввода меняет модель беседы на ходу. Профили, подсказка агента
(`agent/config/suffix.md`) и прочие отличия от настроек OpenHands по умолчанию хранятся в git:

```bash
python3 -I agent/config.py check   # что на сервере агента разошлось с git (без значений)
python3 -I agent/config.py apply   # записать профили и настройки, включить активный профиль
```

Профиль дополняет общую часть `profiles.json`, вложенные объекты сливаются по ключам. Выборка —
по карточкам моделей: Nex N2.5 — 0.7 / top_p 0.95 / top_k 40, Tess и Holo4 (Qwen3.8) —
1.0 / 0.95 / 20, min_p 0. `send_reasoning_content` в `capability_overrides` возвращает модели её
прошлые размышления: Tess (карточка: preserve_thinking в агентных циклах) и Nex (шаблон всегда
их выводит) — да, Holo4 — нет (её harness их не повторяет). agent-server 1.58 этот ключ не
читает: до релиза с PR OpenHands/software-agent-sdk#4446 его учитывает `agent/sdk-patch`.
Там же исправлен подсчёт токенов после смены модели или уровня рассуждений (иначе индикатор
контекста пишет «данных пока нет»; #5639). Зациклившееся размышление (длинная фраза 3+ раза)
уходит модели без повторов — иначе она продолжала петлю в следующих шагах; в беседе хранится
оригинал. На бюджете размышления (`thinking_budget_tokens`) сервер завершает мысль фразой
`budget_message` из `llama-swap.yaml`, а не обрывает её на полуслове.

Сжатие беседы начинается с 70% окна модели (`max_input_tokens` профиля; потолок 160000 —
`condenser` в `settings.json`): ранние шаги заменяет журнал шагов, собранный без обращения к модели.
Свежие из них — с аргументами и выжимкой результата, старые — строкой; сообщения пользователя
и отказы стража — дословно; журнал прошлого сжатия сворачивается в строки
(`agent/sdk-patch/nexus_ledger.py`). Резюме самой моделью остаётся на пределе контекста
и на случай, если журнал перерос четверть порога. Пересказ модели может потерять запрет
или текущую просьбу, поэтому над ним всегда стоят слова пользователя из забытой части:
его сообщения дословно (до 10% порога) и последний ответ агента. Каждое сообщение — целиком
или никак, без обрезки. Не влезают — все они дословно сохраняются в файл
`agent/state/nexus-user-words/`, а в блоке остаются указание прочитать этот файл перед следующим
шагом, первое сообщение и самые новые, пропущенные отмечены числом на своём месте. Следующий журнал
или блок берёт слова из этого файла. В контексте бесконечную беседу целиком не хранит ничто:
шаги между сообщениями сжимаются.

Пределы ожидания модели (`profiles.json`): 2400 с на попытку и 600 с молчания потока — чтение
100–200 тыс. токенов молчит дольше двух минут, а ik_llama не сообщает в поток, как далеко дочитал.
Поэтому строка состояния не ждёт тайм-аута: раз в 1,5 с она читает `/metrics` модели (числа, без
текста; через шлюз `/llm/model/<id>/metrics`). ik_llama помечает запрос занятым только пока
модель пишет, поэтому: растёт KV-кэш при свободном слоте — «Модель читает контекст»; слот занят —
«Модель пишет ответ»; кэш стоит или сервер молчит 2 минуты — «Модель не продвигается больше 2 минут —
возможно, зависла» (тогда задачу можно остановить). Загрузку модели показывает llama-swap: «Модель
загружается».

Экран агент видит и трогает командами из `screen/bin` (`screenshot`, `click`, `key`, `text`,
`focus`…; описание — `desk skill`). Строка `@@attach <картинка>` в их выводе становится
изображением в результате команды, как в обвязке, на которой обучена Holo4: до 1920 px, JPEG 85
(`agent/sdk-patch/nexus_screen.py`).

## Проверки

```bash
./check   # все слои по очереди и итог строкой на слой; код 1, если что-то не прошло
```

`./check` ничего не собирает и не запускает: тестам интерфейса нужна готовая `ui/dist` (браузерные
проверки: Firefox, Chrome), сверке настроек — запущенный агент; без них слой пропускается с причиной.
Слои: готовность к запуску, интерфейс (`ui`: `npm test`, в том числе одинаковость маршрутов
стенда разработки и шлюза по `gateway/routes.json`), страж, голос (произношение, служба, сверка
моделей), обновления, запуск и смотритель, установка и архив (`install`, `pack`, проверка
архива на этом проекте, список весов против меню), шлюз (настоящий Caddy на свободном порту: маршруты,
заголовки кэша), SDK-патчи, настройки агента против git (`agent/config.py check`).
Отдельно, с сетью: `update/nexus-update check` — что можно обновить.

Проверку SDK-патчей `./check` запускает тем же окружением uv, что Canvas даёт agent-server
(без сети; до первого запуска Nexus окружения нет, и слой пропускается). Она проверяет стража
в прямой SDK-беседе, блокировку при сбое хука, сохранение запретов пользователя через несколько
сжатий и смену модели, передачу изображения в модель.

TypeScript-проверки типов нет намеренно: надстройка подменяет внутренние модули Canvas, у которых
нет описаний типов, а поведение держат тесты и сборка.

Стенд интерфейса без настоящих служб — `ui/dev/README.md`.

Вне git и только в личной копии (`./pack personal`): `~/.config/openhands-nexus/session.env` (ключ

не читаются), корневой сертификат `gateway/ca/openhands-ca.{crt,key}` («OpenHands Local Root CA»,
до 2036 г., уже установлен на планшете) и `agent/state/` (беседы). Потерян сертификат — выпустить
новый корневой, положить в `gateway/ca/` и заново установить на планшет с `http://<адрес ПК>:8081/ca.crt`:

```bash
openssl req -x509 -newkey rsa:4096 -sha256 -days 3650 -nodes -subj "/CN=OpenHands Local Root CA" \
  -addext "basicConstraints=critical,CA:TRUE" -addext "keyUsage=critical,keyCertSign,cRLSign" \
  -keyout gateway/ca/openhands-ca.key -out gateway/ca/openhands-ca.crt
```

`python3 -I agent/config.py apply` после первого запуска — профили и настройки из git) → `./check`.

## Архивы

```bash
./pack            # чистый архив последнего коммита: ~/Nexus-архивы, пять последних, рядом .sha256
./pack personal   # личная копия: ~/Nexus-архивы/личное, 0600, три последние
```

Чистый архив — `git archive` (только файлы git и `VERSION` с коммитом), при несохранённых изменениях
`./pack` отказывает. До сохранения архив проверяет `launcher/archive.py scan`: нет состояния агента,
ключей, сертификатов, весов, сборок, программ (ELF), ссылок за пределы проекта, файлов больше 1 МБ, строк вида ключей
и значений ключей этого ПК из `session.env`; установщик и документы на месте и исполняемы.
Проблема называется путём, найденный текст не печатается.

Рядом, один раз на коммит движка, — архив движка `ik_llama-<коммит>.bundle` с `.sha256`: исходники
ik_llama одним коммитом без истории (git bundle, около 35 МБ). Если он лежит в `~/Nexus-архивы/`,
`./install` берёт исходники из него: выходит такая же git-копия, как от `git clone --depth 1`,
`origin` — GitHub, `nexus-update` работает как обычно. Готовая сборка не переносится: она под процессор
(`GGML_NATIVE`), карты и CUDA своего ПК.

Второй диск для копий: путь одной строкой в `~/.config/openhands-nexus/archive-copy`. После каждого
`./pack` и `./pack personal` там те же файлы, что в `~/Nexus-архивы` (удалённые ротацией удаляются и там);
диск недоступен — архив всё равно сохраняется, копия пропускается.

Личная копия: `session.env`, `gateway/ca/`, `agent/state/`, `~/Nexus` — без `.venv`, `node_modules`,
`__pycache__` (их пересоздают задачи). `./pack restore ФАЙЛ` (его вызывает `./install`) кладёт
её на место: существующее не трогает, файлы вне этих четырёх мест отвергает, ссылки наружу пропускает.
