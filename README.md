# OpenHands Nexus

> **Локальная автономная инженерная рабочая станция на базе OpenHands**  
> Автономная оркестрация локальных LLM (Dual-GPU), адаптивное голосовое управление (STT/TTS), защищённый мобильный PWA Remote Control и динамический Thinking UX.

---

## 1. Архитектурная концепция и статус проекта (Core Architectural Identity)

> [!IMPORTANT]
> **Мы НЕ являемся OpenHands.**  
> Оригинальный OpenHands ([All-Hands-AI/OpenHands](https://github.com/All-Hands-AI/OpenHands)) — это внешний upstream-проект. Его ядро является внешней зависимостью, содержится в исходной структуре репозитория в **абсолютно нетронутом виде** и обновляется напрямую через `git pull` из официального upstream-репозитория.

> **Что такое OpenHands Nexus:**  
> Наш репозиторий — это **OpenHands Nexus**: неинвазивная автономная надстройка (overlay), интеграционный и оркестрационный слой, превращающий OpenHands в защищённую, полностью изолированную (air-gapped) локальную инженерную рабочую станцию на Windows.

### Принципы архитектуры Nexus Overlay
1. **100% неинвазивность (Non-Invasive Overlay)**:  
   Все функции станции реализованы исключительно как внешние модули вокруг оригинального ядра:
   - HTTPS LAN Gateway (обратный mTLS прокси с PWA)
   - Working Profiles Dual-Stack (синхронизация профилей между Node.js и Python)
   - Local Voice Bridge (автономный сервис распознавания русской речи GigaAM v3 и озвучки Supertonic)
   - llama-swap (интеллектуальный динамический роутер локальных LLM с LRU-выгрузкой)
2. **Полная обратимость и безопасность обновлений (Idempotent Patchers)**:  
   Все модификации фронтенда (сенсорные кнопки 48px, селекторы Thinking, русская локализация) накладываются идемпотентными скриптами с автоматическим резервным копированием и восстановлением (`OpenHands-Update/scripts/`). Обновление upstream OpenHands выполняется без конфликтов и риска потери доработок.
3. **Полная изоляция (Air-Gapped Local Operation)**:  
   Станция работает строго автономно: промпты, код, диалоги и аудиопотоки не передаются на внешние облачные сервисы.

## 2. Аппаратная платформа и спецификации (Hardware Ceiling)

- **Системная память (RAM):** Строго **48 GB** (47.92 GB физически доступно, DDR4), **НЕ 64 GB**.
- **Dual GPU Setup (Общий пул VRAM ~37.9 GB):**
  - **GPU 0:** NVIDIA GeForce RTX 5060 Ti (**16 GB VRAM**) — базовая обработка, prefill, UI/PWA, системный десктоп.
  - **GPU 1:** NVIDIA GeForce RTX 2080 Ti (**22 GB VRAM** с аппаратной модификацией) — генерация кода, расширенный контекст до 128K, тяжёлые квантования.
- **Операционная система:** Windows 11 / Windows 10 x64, PowerShell 5.1 / PowerShell 7.
- **Инференс-бэкенд:** `llama-swap` + кастомный движок `ik_llama` с аппаратным тензорным распараллеливанием (`-dev CUDA0,CUDA1 -ts 14,22`), квантованным KV-кэшем (`-ctk q6_0 -ctv q4_0` / `-ctk q8_0 -ctv q5_0`), Flash Attention (`-fa on`), ускорением MTP и контролем аппаратных бюджетов рассуждения (`--reasoning-budget`).

## 4. Ключевые возможности

### 1. Локальный ансамбль моделей (Model Fleet)
Интеграция специализированных локальных моделей через `llama-swap` с динамической ротацией и нулевой утечкой VRAM:
* 👑 **Qwen 3.5 122B A10B LynnStyle (Флагманский супер-инженер)**:
  - 44-ГБ MoE модель (122B параметров, 10B активируемых), работающая локально на двух потребительских GPU и 48 GB RAM.
  - **Революционное ускорение через GPU Hot-Expert LRU кэш (PR #27861)**: ускорение инференса с 8.2 tok/s до **26.5 – 33.0 tok/s** (+284% пиковое ускорение).
  - **Штатный режим (`qwen122`)**: 64 слота кэша в VRAM, полный контекст **128K**, скорость ~26.5 tok/s, запас VRAM > 2 ГБ.
  - **Экстремальный режим (`qwen122-turbo`)**: 80 слотов кэша в VRAM, контекст **96K**, рекордная скорость кодинга **до 33.0 tok/s**.
  - Назначение: глубокий аудит, архитектурный синтез, безопасный рефакторинг комплексных систем.
* ⚡ **Ornith 1.5 Coder 35B (Исполнитель / Скоростной кодер)**: архитектура ICE, прямой синтез чистого кода со скоростью до **79 tok/s** (MTP n_max=1, p_min=0.50), запуск тестов, исправление ошибок.
* 🧠 **Qwen 3.8 27B (Архитектор / Ревьюер / Соло-агент)**: планирование задач, декомпозиция, ревью кода, reasoning-бюджет 4096 токенов.
* 🔬 **Qwen3-Next 80B (Глубокий аналитик)**: многоуровневое рассуждение для сложных архитектурных тупиков и дебага.

### 2. Рабочие профили (Working Profiles) и динамический Thinking UX
Управление всей станцией через единую серверную точку правды (`/api/working-profiles`):
* **Одиночные профили**: Qwen 3.8 (Автономный), Ornith 1.5 Coder (Архитектор), Qwen3-Next 80B (Глубокий Анализ), Qwen 122B (Флагман).
* **Тандемы**: Qwen + Ornith (Кодинг), Qwen + Next (Анализ), Next + Ornith (Кодинг).
* **Team-Full (3 Модели)**: полная автономная триада (Qwen -> Ornith -> Next).
* **Динамические уровни Thinking**:
  * Qwen 3.8: *Direct* (без рассуждений), *Low* (быстрое), *Medium* (сбалансированное), *High* (максимальное).
  * Qwen3-Next: *Normal* (2048 токенов), *Deep* (4096 токенов).
  * Ornith: фиксированный режим быстрого кодинга.
  * Team-Full: *Стандартная команда*, *Глубокая команда*.

### 3. Удалённое управление через Mobile LAN PWA
* Полноценная установка на Android / планшеты (Samsung Galaxy Tab S9 Ultra и др.) как нативное PWA.
* Двусторонняя синхронизация верхней панели профиля и нижнего селектора composer (`+ Qwen3.8-Medium`, `+ Ornith-Coding` и т.д.).
* Защита от схлопывания мобильного селектора моделей при изменении размера экрана и экранной клавиатуры.
* Сенсорные области с соблюдением стандарта доступности (48px / 52px).

### 4. Нейро-голосовой интерфейс (Local Voice UI)
* Распознавание русской речи (STT): на базе локальной модели **GigaAM v3** (время отклика ~100-300 мс).
* Двухдвижковая озвучка (Dual-Engine TTS): выбор между серверным Supertonic LAN TTS и нативным Android SpeechSynthesis.
* Доступность: статусная плашка «● Голос готов», полная интеграция с фокусом и экранными дикторами.

## 7. Быстрый старт

### 0. Предварительные требования и размещение моделей (Prerequisites & Models)
* **Системные зависимости:**
  * Windows 10/11 x64 (PowerShell >= 5.1)
  * Node.js >= 18 (рекомендуется v20 или v22 LTS)
  * Python >= 3.10 (3.11 или 3.12 x64)
  * Драйвер NVIDIA с поддержкой CUDA 12.x
* **Размещение квантованных весов (`Models/`):**
  Поместите соответствующие `.gguf` файлы в директорию `Models/` (директория исключена из git из-за большого размера):
  ```
  Models/
  ├── Qwen-122b/  -> Qwen3.5-122B-A10B-44GB-GPT5.6Sol-SFT-LynnStyle-GGUF.gguf
  ├── Ornith/     -> Ornith-1.5-35B-MTP-19G-ICE.gguf
  ├── Qwen3.8/    -> Qwen3.8-27B-Opus-Distill-v2-Q4_K_M.gguf (+ mmproj-f16.gguf)
  └── Qwen3-Next/ -> Qwen3-Next-80B-A3B-Thinking-UD-Q3_K_XL.gguf
  ```

### 1. Первичная настройка на новом ПК (First-Time Setup)
```cmd
SETUP-OPENHANDS-LOCAL.cmd
```
Автоматически инициализирует пользовательские шаблоны профилей в `%USERPROFILE%\.openhands`, проверяет SSL-сертификаты PWA, настраивает правило Брандмауэра Windows и накладывает необходимые патчи Custom Layer.

### 2. Проверка системных зависимостей
```cmd
CHECK-DEPENDENCIES.cmd
```
Запускает комплексные тесты системы (Windows 11, Node.js, Python, GigaAM v3, Supertonic 3, CUDA/VRAM, патчи Agent Canvas, SSL-сертификаты и сетевые порты).

### 3. Запуск и остановка станции
```cmd
START-OPENHANDS-LOCAL.cmd     :: Запуск всех сервисов платформы
STOP-OPENHANDS-LOCAL.cmd      :: Корректная остановка всех сервисов
RESTART-OPENHANDS-LOCAL.cmd   :: Перезапуск станции
```
Скрипт проверяет порты, запускает llama-swap (:8080), голосовой мост (:18002), agent-server (:18000), agent-canvas (:8000) и lan-gateway (:8443).

### 4. Резервное копирование и восстановление
```cmd
BACKUP-OPENHANDS.cmd          :: Быстрый бэкап конфигурации, профилей, состояния пользователя
RESTORE-OPENHANDS.cmd         :: Автоматическое восстановление из последнего бэкапа
RECOVER-OPENHANDS-LOCAL.cmd   :: Аварийное восстановление (снятие блокировок, освобождение портов)
```

### 5. Запуск валидационных тестов
```cmd
python Tests/runner.py --unit
```
Выполняет запуск набора модульных тестов с проверкой всех подсистем станции.

### 6. Доступ
* **Рабочий стол ПК**: http://127.0.0.1:8000
* **Мобильные устройства в LAN (Wi-Fi)**: https://192.168.0.14:8443 (или локальный IP ПК в вашей сети)

### 7. Диагностика
```cmd
DIAGNOSTICS-OPENHANDS-LOCAL.cmd
```

## 8. Безопасность и конфиденциальность

* Станция работает **100% локально** без отправки промптов, кода или голоса на внешние сервера.
* Приватные ключи сертификатов (`*.key`, `*.pfx`) и токены авторизации надежно исключены из репозитория через `.gitignore`.
* Все сетевые входящие точки экранированы: проверка допустимых MIME-типов, валидация путей (Path Traversal Protection), лимиты на размер входящих тел запросов (DoS Protection) и строгие заголовки безопасности (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`).
